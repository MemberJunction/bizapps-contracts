So the billing EVENT is a contracts concept and its failures are surfaced here, even though three of these four are fixed by editing a price list over in orders. "Estimated" is honest, not hedging. The number is what Orders.PreviewOrder returns for the draft as it stands today; the actual bill is priced again at generation time. If those two ever disagree, the cause is a pricing change between now and then — which is exactly the AsOf question on PR #1.

"Dry run" is a proposal, not a built thing. The engine has one path — Contracts.GenerateBillingEvent, all-or-none, which materializes an order. A preview that assembles the draft and prices it through Orders.PreviewOrder without calling CreateOrderInState would be a genuinely useful safety rail before a large run, and it costs one extra operation.
